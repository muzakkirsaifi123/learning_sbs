# MuzOps Learning Zone

## Purpose

This is a personal learning knowledge base for DevOps, Kubernetes, Kafka, and Cloud Engineering.

Notes are written in **Notion** and automatically synced to this repo as Markdown files. The site is built with **MkDocs Material** and published to **GitHub Pages**. Every page here is something worked through hands-on — no copy-paste theory.

What's inside:
- **Kubernetes** — operators, controllers, CRDs, reconcile loops
- **Kafka** — architecture, schema registry, cp-schema internals
- **Notion Sync** — pages pulled from Notion and auto-published here

## Local Setup

### 1. Clone the repo

```bash
git clone https://github.com/saifi/learning_sbs
cd learning_sbs
```

### 2. Install dependencies

```bash
pip install -r requirements.txt
```

Versions are pinned deliberately — see the comments in `requirements.txt` before bumping `mkdocs-redirects` or `mkdocs-rss-plugin` past their pinned versions.

### 3. Create your `.env` file

Copy the example and fill in your values:

```bash
cp .env.example .env
```

Edit `.env`:

```
NOTION_TOKEN=ntn_xxxxxxxxxxxxxxxxxxxx
NOTION_PAGE_ID=1fd9f2a93248826a83de816c57fc66b8
```

**How to get these values:**
- `NOTION_TOKEN` — go to [notion.so/profile/integrations](https://www.notion.so/profile/integrations), create an Internal integration, copy the token
- `NOTION_PAGE_ID` — open your Notion page, copy the last part of the URL: `notion.so/Page-Title-**<this-part>**`
- Share your Notion page with the integration: open the page → `...` → Connections → select your integration

## Run Locally to Validate

### Sync pages from Notion

```bash
NOTION_TOKEN="ntn_xxx..." NOTION_PAGE_ID="1fd9f2a9..." python3 notion_sync.py
```

This will:
- Pull all pages from your Notion root page
- Save them as `.md` files under `docs/notion/`
- Auto-update the `nav` section in `mkdocs.yml`
- Regenerate `docs/index.md` with quick links

### Preview the site in browser

```bash
mkdocs serve
```

Open [http://127.0.0.1:8000](http://127.0.0.1:8000) — live reloads on every file change.

### Validate the build (strict mode)

```bash
mkdocs build --strict
```

`--strict` treats warnings as errors — same behaviour as the CI pipeline.
If this passes locally, the pipeline will pass too.

### Run the test suite and quality checks

```bash
python3 -m pytest tests/ -v      # sync-engine + doc-quality-check tests, no Notion credentials needed
python3 scripts/check_docs.py    # broken links, invalid front matter, orphan/thin pages
```

## Run from Pipeline (GitHub Actions)

### Step 1 — Add GitHub Secrets

Go to your repo → **Settings → Secrets and variables → Actions → New repository secret**

Add both:

| Secret name | Value |
|-------------|-------|
| `NOTION_TOKEN` | Your `ntn_xxx...` token |
| `NOTION_PAGE_ID` | Your Notion page ID |

### Step 2 — Enable GitHub Pages (one-time)

Go to repo → **Settings → Pages**

- Source: `Deploy from a branch`
- Branch: `gh-pages` / `/ (root)`
- Save

Your site will be live at `https://<username>.github.io/<repo>/`

### Step 3 — Trigger workflows

**Sync Notion pages manually:**
1. Go to repo → **Actions** tab
2. Select **Sync Notion to MkDocs**
3. Click **Run workflow → Run workflow**

**Deploy site manually:**
1. Go to **Actions → Deploy MkDocs → Run workflow**

Or simply push any change to `main` — deploy triggers automatically.

### Automated schedule

| Workflow | Runs automatically |
|----------|--------------------|
| `notion_sync.yml` | Every 3 hours — syncs Notion → validates (`check_docs.py` + `mkdocs build --strict`) → commits to `main` only if that passes |
| `deploy.yml` | On every push to `main` — quality check, `mkdocs build --strict`, then publishes to GitHub Pages |
| `branch-preview.yml` | On every push to any branch **except** `main` — builds and deploys to `https://<username>.github.io/<repo>/preview/<branch-name>/`, no PR required. Deleting the branch removes its preview automatically. |

Full automated flow:

```
Write notes in Notion
      ↓  every 3 hours  (notion_sync.yml — commits only if it validates clean)
docs/notion/*.md saved and committed to main
      ↓  on push to main  (deploy.yml — strict build gate, then deploy)
MkDocs site built and published to GitHub Pages

Push to any other branch
      ↓  (branch-preview.yml)
Live preview at /preview/<branch-name>/ — check it before merging to main
```

```

├── docs/
│   ├── index.md                        # Home page (auto-generated by notion_sync.py)

│   ├── assets/
│   │   ├── extra.css, logo.svg         # Site chrome
│   │   ├── recent.js                   # Recently-read tracker (localStorage)
│   │   ├── mathjax.js                  # pymdownx.arithmatex config

│   │   ├── graph.json                  # Regenerated by scripts/generate_graph.py
│   │   └── notion-images/              # Downloaded Notion images (see notion_sync.py)
│   ├── kubernetes_operators/
│   │   └── kubernetes_operator.md      # Hand-written, not Notion-synced
│   └── notion/                         # Auto-generated — a PR editing this gets reverted
│
├── snippets/                           # pymdownx.snippets reusable blocks (--8<--)
├── overrides/404.html                  # Custom 404 via theme.custom_dir
├── scripts/
│   ├── check_docs.py                   # Broken links / front matter / orphan pages
│   └── generate_graph.py               # Builds docs/assets/graph.json
├── tests/                              # Sync-engine + doc-quality-check tests (mocked, no Notion needed)
├── .notion-sync/manifest.json          # Page-ID tracking — what makes sync idempotent
│
├── .github/
│   ├── workflows/
│   │   ├── deploy.yml                  # Strict build + deploy to GitHub Pages on push to main
│   │   ├── notion_sync.yml             # Sync Notion → validate → commit (scheduled)
│   │   └── branch-preview.yml          # Push to any branch → live preview, no PR needed
│   └── ISSUE_TEMPLATE/
│
├── notion_sync.py                      # Notion sync engine (run locally or via CI)
├── hooks.py                            # mkdocs build hook: "edit on Notion" button
├── mkdocs.yml                          # MkDocs site configuration
├── requirements.txt                    # Pinned dependencies for local dev and both workflows
├── .env.example                        # Environment variable template
├── CONTRIBUTING.md                     # What's Notion-generated vs. a normal PR target
└── README.md                           # This file
```
